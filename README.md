# 《轻眸识刻》组织全局配置与维护指南

> **仓库属性**：`QingMouFoodDate` GitHub 组织特殊全局配置仓库  
> **核心用途**：托管组织公开官方主页展示内容、全局社区规范与跨仓通用配置

---

## 一、 仓库定位与核心职责

本仓库是 GitHub 官方约定的特殊组织配置仓库，核心承担以下两项职能：

1. **组织官方主页门户**：托管 `profile/README.md`，作为访问组织主页（`https://github.com/QingMouFoodDate`）时向公众、评审专家与开发者展示的权威门面；
2. **组织级全局配置预留**：集中管理跨仓库通用的社区健康规范、全局 Actions 工作流与通用模版。

---

## 二、 推荐目录架构

```text
.github/
├── README.md                      # 组织全局配置与维护指引文档
└── profile/                       # 组织官方公开主页展示内容目录
```

- **`README.md`**：本说明文档，指导组员如何维护与扩展组织全局配置；
- **`profile/README.md`**：组织官方公开主页展示源文件，由 GitHub 官方引擎直接解析渲染至组织首页。

---

## 三、 组织官方主页维护流程

当项目技术演进、仓库定位调整或新增交付成果时，按以下流程维护组织主页：

1. **主页内容源**：直接编辑本仓库下的 `profile/README.md`；
2. **内容定位要求**：
   - 聚焦于系统核心业务主线（找得到、读得准、判得清、能改进）；
   - 准确反映 6 大核心代码仓库的职责矩阵与定位；
   - 严格引用 `ProjectPRD` 下的最新单一事实来源（SSOT）契约与标准；
3. **推送与生效**：修改通过代码审查并合并入 `main` 分支后，组织首页将自动秒级实时刷新。

---

## 四、 组织级全局资源预留指引

后续随着团队协同深入，可在本仓库渐进式扩展以下全局能力：

### 1. 组织级 Issue 与 Pull Request 模板
- 若需为全域 6 个代码仓库统一缺陷报告（Bug Report）与功能特性（Feature Request）提单格式，可在本仓库根目录下创建 `ISSUE_TEMPLATE/` 与 `PULL_REQUEST_TEMPLATE.md`；
- 所有未单独配置模板的代码仓库将自动继承本仓的全局模版。

### 2. 组织级代码安全与行为准则
- 可在此统一部署组织级开源行为守则 `CODE_OF_CONDUCT.md` 与安全漏洞报告政策 `SECURITY.md`，向全域仓库生效默认安全策略。
